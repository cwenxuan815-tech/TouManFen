## 四、模型量化（03-bert/模型量化_DQ.py，动态量化 DQ）

脚本原样运行：`torch.quantization.quantize_dynamic(model, {nn.Linear}, dtype=torch.qint8)`，CPU + onednn 引擎。

| 项目 | 结果 |
|---|---|
| 量化前（1 万条 dev） | macro F1 **0.9249** / acc 0.9245 / P 0.9268 / R 0.9245 |
| 量化后（1 万条 dev） | macro F1 **0.9201** / acc 0.9198 / P 0.9214 / R 0.9198 |
| **精度损失** | **仅 -0.47 个点**（资料称"F1 仅降 4 个多点"，我们这里好得多） |
| 模型体积 | 409.2 MB → **152.7 MB（2.68x 压缩）** ✅ 与资料"390M→145M"一致 |
| 预测一致性 | 4 条样例 fp32 与 int8 预测**完全一致** |
| 前向加速（干净环境实测） | batch=1 **1.78x**、batch=4 **2.30x**、batch=16 1.14x、batch=64 **1.64x** |
| 产物 | `03-bert/save_model/quantization_model.pkl` |
| 脚本总耗时 | 545.7 秒（主要是 2 次 1 万条 dev 评估） |

> 注意：量化提速与 batch 强相关（小 batch 收益更明显）。若与其它重任务并行会测到"变慢"的假象（第一次在剪枝并行时测得 0.34x，干净环境复测为 1.6~2.3x）。另外 `torch.quantization` 在 torch 2.14 已标记弃用（建议迁移 torchao），当前仍可用。

## 五、模型剪枝（06-prune/model_prune.py，全局非结构化 30%）

对 12 层 encoder 的 attention q/k/v 权重做 L1 全局非结构化剪枝 30%，`prune.remove()` 固化。

| 项目 | 结果 |
|---|---|
| 剪枝前（1 万条 dev） | macro F1 **0.9249** / acc 0.9245 |
| 剪枝后（1 万条 dev） | macro F1 **0.9239** / acc 0.9237 |
| **精度损失** | **仅 -0.10 个点**（BERT 对该比例非结构化剪枝很鲁棒） |
| 稀疏度 | 30.00%（48 个注意力 Linear 模块，共 28,311,552 个权重，占全模型 27.7%） |
| **模型体积** | 390.2 MB → **390.2 MB（不变）** ⚠️ 零权重仍以稠密 fp32 存储 |
| 产物 | `06-prune/save_model/before_prune_model.pkl`、`after_prune_model.pkl` |
| 脚本总耗时 | 705.3 秒（主要是 2 次 1 万条 dev 评估） |

> 结论：**非结构化剪枝 + 固化不减小体积、也不提速**，只提高稀疏度；若要"压缩"结论成立需改结构化剪枝或稀疏导出。但"精度几乎无损"可以作为抗剪枝能力的正面结论。

## 七、模型蒸馏（v1 基线 + v2 改进版）

教师：BERT 全量微调（dev 0.9249 / test 0.9307）。
蒸馏超参：T=2、α=0.7，loss = (1-α)·CE + α·T²·KL，1 万条 dev 做验证。

### v1（`model_distll.py`，参考代码原样）

学生 BiLSTM（embed **128** / hidden 256 / 3 层，6.65M 参数），lr=5e-5，1 epoch。

| 项目 | 结果 |
|---|---|
| 训练用时 | 2 小时 13 分（2.84 s/step，教师每步都要前向） |
| 学生 dev 最佳 F1 | 0.7989（@step 2500） |
| 独立 test 集 | **macroF1 0.8021**（1 万条推理 23 秒） |
| 体积 / 压缩比 | 26.6 MB（**14.7x**） |

> 问题：精度掉 12.9 个点，甚至低于随机森林（0.8302）。根因是**学生词嵌入随机初始化** + 1 epoch。

### v2（`distill_v2.py` + `student_bilstm_v2.py`，本轮改进）⭐

三处改动：① 用教师 BERT 词嵌入矩阵 **SVD(768→256)** 初始化学生 embedding；② **教师 logits 预计算缓存**（学生每步不再跑教师，单步 2.84s→~1s）；③ 学生升级为 embed 256 / hidden 256 / 3 层（9.62M），lr=1e-3，6 epoch + 早停。

| 项目 | v1 | **v2** | 变化 |
|---|---|---|---|
| 学生结构 | embed 128 / 9.62M? → 6.65M | embed 256 / **9.62M** | 容量 +45% |
| 训练用时（学生训练段） | 2h13m（含每步教师前向） | **2h22m**（教师预计算另约 2h，可复用） | 可跨实验复用缓存 |
| dev 最佳 F1 | 0.7989 | **0.8930** | **+9.4 点** |
| **独立 test macroF1** | 0.8021 | **0.8974** | **+9.5 点** |
| test accuracy | 0.8021 | **0.8975** | +9.5 |
| 体积 | 26.6 MB（14.7x↓） | 36.7 MB（**10.6x↓**） | 略大但精度大幅提升 |
| 1 万条推理 | 23 s | **12 s**（833 条/秒） | 快约 2 倍 |
| 与教师差距 | -12.86 | **-3.33 点** | 缩小 9.5 点 |

**v2 每 epoch dev F1**：0.8661 → 0.8801 → 0.8877 → 0.8879 → 0.8875 → **0.8930**（仍在缓升，可再跑 1~2 epoch）。

### v2b（v2 续训 + 清洗后数据）⭐ 当前最优学生

在清洗后的训练集（178,692 条，见 [00-data/data/clean_report.md](../00-data/data/clean_report.md)）上，
从 v2 权重继续训练 2 epoch（lr 3e-4），并复用已缓存的教师 logits（按清洗索引过滤，未重算教师）。

| 项目 | v2 | **v2b** | 变化 |
|---|---|---|---|
| dev 最佳 F1 | 0.8930 | **0.9022**（epoch 1 达到；epoch 2 为 0.8988） | **+0.9 点，突破 0.90** |
| **独立 test macroF1** | 0.8974 | **0.9074** | **+1.0 点** |
| test accuracy | 0.8975 | **0.9075** | +1.0 |
| 体积 / 压缩比 | 36.7 MB / 10.6x | 36.7 MB / 10.6x | 不变 |
| 1 万条推理 | 12 s | 13 s | 基本不变 |
| 与教师差距 | -3.33 | **-2.33 点** | 缩小 1 点 |
| 续训用时 | — | 40m24s（2 epoch，无教师前向） | 缓存复用 |

> 结论：**蒸馏学生最终达到 test macroF1 0.9074**（v1 0.8021 → v2 0.8974 → v2b 0.9074），
> 体积仅 36.7 MB（教师的 1/10.6）、推理 13 秒/万条（教师的 26 倍速），与教师差 2.33 个点。
> 服务已切到 v2b（`05-distill/config.py` 默认 `student_v2b.pkl`；v1/v2 权重保留可对照）。

## 八、主口径总对比（未清洗数据，独立 `test.txt` 1 万条）

> 主口径说明：除第 7 行（蒸馏 v2b 用清洗集训练）外，其余模型均由**未清洗的原始 180,000 条**训练；
> 该例外在表中已标注，其详情见第七章与第九章。

| # | 模型 | 体积 | macroF1 | accuracy | 1 万条推理耗时 |
|---|---|---|---|---|---|
| 0 | 随机森林（TF-IDF） | 1,512 MB | 0.8302 | 0.8293 | **1.2 s** |
| 1 | fastText 词级 auto | 451 MB | 0.9173（P@1） | 0.9173 | 秒级 |
| 2 | **BERT 全量微调（fp32）** | 390.2 MB | **0.9307** | 0.9305 | 339 s |
| 3 | BERT 量化 int8（DQ） | **152.7 MB**（2.68x↓） | 0.9263 | 0.9261 | **120 s（2.8x↑）** |
| 4 | BERT 剪枝 30%（非结构化） | 390.2 MB（不变） | 0.9294 | 0.9293 | 336 s |
| 5 | 蒸馏 BiLSTM 学生 v1（参考代码原样） | **26.6 MB**（14.7x↓） | 0.8021 | 0.8021 | 23 s（15x↑） |
| 6 | 蒸馏 BiLSTM 学生 v2（SVD 初始化 + 6 epoch） | **36.7 MB**（10.6x↓） | 0.8974 | 0.8975 | **12 s（28x↑）** |

**关键结论**
1. 递进链路成立且**独立测试集上 BERT 达到 0.9307，与资料声称的 93.17% 基本一致**（差 0.1 个点）。
2. 量化是最划算的优化：体积降到 39%、速度提升 2.8 倍，精度只掉 0.44 个点。
3. 剪枝 30% 精度几乎无损（-0.13），但**不减小体积**，属于"鲁棒性/稀疏化"实验而非压缩手段。
4. 蒸馏改进链：v1 **0.8021** → v2（SVD 初始化 + 教师缓存 + 6 epoch）**0.8974** →
   v2b（续训 2 epoch + 清洗数据）**0.9074**；压缩 10.6x、推理 26 倍于教师，与教师仅差 2.33 个点。
5. 随机森林 1 万条推理只要 1.2 秒，适合作为低延迟/高召回基线。
6. "精度最高"是 BERT 微调（0.9307），"最优性价比"是量化 BERT（0.9263 / 152.7MB / 120s），
   "最轻量可用"是蒸馏 v2b（0.9074 / 36.7MB / 13s）。
7. 数据清洗（去重 809 + 标签冲突 96 + 防泄漏 403，共删 0.73%）后蒸馏学生 +1.0 点，
   说明清洗对最终指标有实际正收益（注：RF/fastText/BERT 仍用未清洗数据训练，口径已标注）。

> 单位说明（2026-10-20 按字节基数核对，见 [阶段0-工程基线报告](阶段0-工程基线报告.md) §3.6 / X-03）：本表"体积"**混用了两种口径**，不是全部按 1 MB = 10⁶ 字节计算。例如 `bert.pkl` 的 390.2 是 MiB（409,169,600 B ÷ 2²⁰）、`quantization_model.pkl` 的 152.7 是 MB（152,655,460 B ÷ 10⁶）、`student_v2b.pkl` 的 36.7 是 MiB（38,490,838 B ÷ 2²⁰）。**不要用本表数值做跨模型的精确体积比较**；需要精确值时使用字节基数。本表指标数值未改动，仅修正单位注解。

## 九、实验章节：数据清洗与清洗集重训（不计入主口径）

> 本章是**附加实验**：主口径（第八节）仍使用未清洗数据。清洗产物保留在 `*_clean.pkl`，服务端不加载。

### 9.1 清洗做了什么

`tools/clean_data.py`，清洗后训练集 **180,000 → 178,692**（删除 1,308 条，0.73%）：

| 类型 | 删除条数 | 说明 |
|---|---|---|
| 重复标题（去空白归一化） | 809 | 同标题重复，对训练无实质增益 |
| 同标题不同标签（冲突） | 96（46 组） | 标注噪声 |
| 与 dev/test 重叠 | 403 | 防止训练集泄漏到评估集（test 有 110 条与 train 同标题，占 1.1%） |

报告：[00-data/data/clean_report.md](../00-data/data/clean_report.md)；保留样本原始行索引：
`05-distill/cache/train_keep_idx.npy`（供蒸馏按索引复用教师 logits，省约 2 小时重算）。

### 9.2 清洗集重训 RF / fastText

用清洗后的 178,692 条重训，产物 `rf_clean.pkl`、`tfidf_clean.pkl`、`*_train_clean.pkl`（旧模型保留）。
评估仍在**未改动的独立 test.txt（1 万条）**上进行。

| 模型 | 旧（未清洗训练） | 新（清洗训练） | 变化 |
|---|---|---|---|
| 随机森林（macroF1） | 0.8302 | **0.8314** | +0.0012 |
| fastText 字符-手动 | 0.8706 | 0.8714 | +0.0008 |
| fastText 字符-auto | 0.9140 | **0.9145** | +0.0005 |
| fastText 词-手动 | 0.9089 | 0.9094 | +0.0005 |
| fastText 词-auto | 0.9173 | 0.9075 | **-0.0098** |

**结论**
- 清洗（仅删 0.73%）对 RF/fastText 指标**没有实质影响**，变化都在 ±0.1 点内 —— 与预期一致。
- `word_auto` 的 -0.0098 不是数据原因，而是**限时随机调参的波动**（本轮 auto 选中了 dim/bucket 更小的配置，
  模型体积 49MB vs 上轮 431MB）；char-auto 反而略升到 0.9145。
- 因此"清洗集重训"对 RF/fastText 属于**口径校验收尾**，不是精度提升手段。

### 9.3 唯一采用清洗集的正式模型：蒸馏 v2b

清洗的增量成本几乎为零，且带来 +1.0 点）。其余模型**没有**为清洗重训，理由见下：

### 9.4 为什么不给 BERT 做清洗重训（决策记录）

- 清洗只动了 0.73%，其中泄漏样本 403 条（占训练 0.22%）、冲突噪声 96 条（0.05%）；
- 对现有 BERT 指标的影响上限约 **0.1 个点**（test 中 110 条泄漏样本，多为易样本），完全落在 epoch 间波动（±0.3）内；
- 重训成本 5.3 小时/epoch，且会级联要求重做量化、剪枝、蒸馏教师（再 2~3 小时）；
- **决策：不重训**。若需严谨口径，改用"在 test 上剔除 110 条泄漏样本后重算指标"（约 10 分钟），而非重训。
