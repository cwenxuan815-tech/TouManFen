# 接口变更记录（2026-10-21 至 2026-10-22）

> 本文件记录本轮工程实施新增/扩展的 HTTP 契约。所有接口均在后端实现并通过对应验收脚本；前端已按此对接。凡未实现的 LLM 基准/展示均显式标注，不用 mock 冒充真实数据。

## 1. 扩展：分类与对比字段

### `POST /api/v1/classify`
新增字段（向后兼容，缺省 `null`/`false`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `scores` | object\|null | 未校准原始分数（按 class_id） |
| `score_kind` | `raw_proba`/`raw_fasttext`/`raw_softmax`\|null | 分数来源；无分数 null |
| `top_k` | array\|null | `[{class_id,score}]`，降序 |
| `rejected` | bool | 软拒识标记；仍保留 pred_class/分数 |
| `reject_reason` | `low_max_score`/`high_entropy`\|null | 拒识原因 |
| `threshold_meta` | object\|null | 来源=合成负样本、calibrated=false、阈值/样本/适用范围；无分数/未启用为 null |
| `data_source` | `live`/`mock`/`unknown`\|null | 由 worker `/metadata.display_name` 判定，不猜 live |
| `human_feedback_hint` | `{corrected_class,status:"pending"}`\|null | 相似 pending 反馈参考；不替换预测 |

### `POST /api/v1/compare`
每个结果项新增 `data_source`（含 error 项）；保留 `status/model_id/pred_class/latency_ms/error`。`summary` 结构不变。

### `GET /api/v1/compare/stream`
SSE 新增端点；事件见 `docs/并发与超时契约.md`。`model` 事件带 `data_source`；`summary/done/error` 见契约。

## 2. 新增：反馈

### `POST /api/v1/feedback`
请求：`{client_id,title,model_id,pred_class,corrected_class,score?,source?}`。
成功：`{request_id,feedback_id,status:"pending",total,message:"反馈已提交，待审核"}`。
错误：`FEEDBACK_INVALID`(400)、`FEEDBACK_DUPLICATE`(409)、`FEEDBACK_STORE_ERROR`/`FEEDBACK_UNAVAILABLE`(503)。
去重：`client_id+trim(title)+model_id`。

### `GET /api/v1/feedback/stats`
聚合：`total/pending/by_class/by_model/similar_hits/retention_days`；无原始数据导出。

## 3. 新增：竞技场（B7）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/arena/next` | 匿名题目；candidates 仅 `anon_id/pred_class/latency_ms`，**无 model_id/名称** |
| POST | `/api/v1/arena/vote` | `{client_id,item_id,anon_id}` → 揭晓 selected model、Elo；重复 409、限速 429 |
| GET | `/api/v1/arena/leaderboard` | `data_kind=vote`、Elo/votes/Wilson；n<50 `warming_up` 且 rank=null |

Elo 表示人类偏好，不是准确率；固定说明“人类偏好投票强度，仅作演示参考”。

## 4. 新增：启动数据来源状态（F15）

`GET /api/v1/demo/state` → 只读、不触发模型推理：

```json
{"request_id":"...","data_source":"mock|live|unknown","ready_models":5,"total_models":5,
 "mixed":false,"reason":"all_workers_ready_same_source",
 "source_counts":{"mock":5},
 "worker_sources":[{"model_id":"rf","worker_id":"rf","ready":true,"metadata_available":true,
                    "data_source":"mock","display_name":"mock-rf"}]}
```

规则：worker `/metadata.display_name` 以 `mock-` 开头=mock，非 mock 有效字符串=live；metadata 缺失/非法/worker down=unknown。仅当全部已启用模型 ready 且来源一致返回 mock/live；混合或部分不可判定返回 unknown（`mixed`/`reason` 说明），不因可达/进程存活报 live。`cached` 仅由前端快照成功加载后标注。

## 5. 新增：离线基准（B8）

`GET /api/v1/bench/pk` → `{request_id, artifact_path, artifact}`。
`artifact` 为最新 `artifacts/bench/pk_*.json`；当前 4 个本地模型为 `ok`，**LLM 为 missing（外部 Provider 未授权）**；`derived` 为加权投票集成/oracle，均非独立模型。
缺失产物 404 `BENCH_ARTIFACT_NOT_FOUND`；非法 503 `BENCH_ARTIFACT_INVALID`。

## 6. 新增/扩展错误码

- B3：`INVALID_MODEL_OUTPUT`/`REJECTED` 等已有；拒绝为软拒识，不返回分类失败。
- B4：`FEEDBACK_INVALID`、`FEEDBACK_DUPLICATE`、`FEEDBACK_STORE_ERROR`、`FEEDBACK_UNAVAILABLE`。
- B7：`ARENA_NO_ITEMS`、`ARENA_UNAVAILABLE`、`ARENA_ITEM_NOT_FOUND`、`ARENA_ANON_INVALID`、`ARENA_DUPLICATE_VOTE`、`ARENA_RATE_LIMITED`、`ARENA_STORE_ERROR`。
- B8：`BENCH_ARTIFACT_NOT_FOUND`、`BENCH_ARTIFACT_INVALID`。
- B9：默认 compare 不含 LLM；显式选择仍可；LLM 离线时 `partial`，不伪造结果。

## 7. 配置项

| 变量 | 默认 | 说明 |
|---|---|---|
| `TMF_COMPARE_CONCURRENCY` | 3 | compare/stream 并发上限（1–10） |
| `TMF_COMPARE_TOTAL_TIMEOUT_MS` | 18000 | 仅 SSE 总截止 |
| `TMF_TORCH_THREADS` | 4 | BERT/蒸馏 worker 线程数（1–64） |
| `TMF_DB_PATH` | `serving/run/tmf.db` | B4/B7 共享 SQLite；演示 seed 强制临时路径 |
| `TMF_BENCH_DIR` | `artifacts/bench` | 仅服务端运维可覆盖的 bench 目录 |

## 8. 已知缺项

- B8 的 LLM 基准缺失，PK 榜显示 missing；不得用 mock 填补。
- F15 页面级自动 cached 快照回退已接线：`frontend/public/snapshot.json` 在后端不可达时由 App 自动加载并展示生成时间；离线状态不伪造 live/mock。
- F13 设备验收为浏览器模拟，不是真实投影/手机/笔记本验收。
- 真实 stage3/真实 LLM 未在本轮运行；B10 用隔离 mock 栈验证。
