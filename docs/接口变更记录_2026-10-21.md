# 接口变更记录（2026-10-21 至 2026-10-25）

> 本文件记录本轮工程实施新增/扩展的 HTTP 契约（覆盖 2026-10-21 至 2026-10-25，最后同步 2026-10-25）。所有接口均在后端实现并通过对应验收脚本；前端已按此对接。凡未实现的 LLM 基准/展示均显式标注，不用 mock 冒充真实数据。

## 1. 扩展：分类与对比字段

### `POST /api/v1/classify`
新增字段（向后兼容，缺省 `null`/`false`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `scores` | object\|null | 未校准原始分数（按 class_id） |
| `score_kind` | `raw_proba`/`raw_fasttext`/`raw_softmax`\|null | 分数来源；无分数 null |
| `top_k` | array\|null | `[{class_id,score}]`，降序 |
| `rejected` | bool | 软拒识标记；仍保留 pred_class/分数 |
| `reject_reason` | `low_max_score`/`high_entropy`\|null | 拒识原因 |
| `threshold_meta` | object\|null | 来源=合成负样本、calibrated=false、阈值/样本/适用范围；无分数/未启用为 null |
| `data_source` | `live`/`mock`/`unknown`\|null | 由 worker `/metadata.display_name` 判定，不猜 live |
| `human_feedback_hint` | `{corrected_class,status:"pending"}`\|null | 相似 pending 反馈参考；不替换预测 |

### `POST /api/v1/compare`
每个结果项新增 `data_source`（含 error 项）；保留 `status/model_id/pred_class/latency_ms/error`。`summary` 结构不变。

### `GET /api/v1/compare/stream`
SSE 新增端点；事件见 `docs/并发与超时契约.md`。`model` 事件带 `data_source`；`summary/done/error` 见契约。

## 2. 新增：反馈

### `POST /api/v1/feedback`
请求：`{client_id,title,model_id,pred_class,corrected_class,score?,source?}`。
成功：`{request_id,feedback_id,status:"pending",total,message:"反馈已提交，待审核"}`。
错误：`FEEDBACK_INVALID`(400)、`FEEDBACK_DUPLICATE`(409)、`FEEDBACK_STORE_ERROR`/`FEEDBACK_UNAVAILABLE`(503)。
去重：`client_id+trim(title)+model_id`。

### `GET /api/v1/feedback/stats`
聚合：`total/pending/by_class/by_model/similar_hits/retention_days`；无原始数据导出。

## 4. 新增：启动数据来源状态（F15）

`GET /api/v1/demo/state` → 只读、不触发模型推理：

```json
{"request_id":"...","data_source":"mock|live|unknown","ready_models":5,"total_models":5,
 "mixed":false,"reason":"all_workers_ready_same_source",
 "source_counts":{"mock":5},
 "worker_sources":[{"model_id":"rf","worker_id":"rf","ready":true,"metadata_available":true,
                    "data_source":"mock","display_name":"mock-rf"}]}
```

规则：worker `/metadata.display_name` 以 `mock-` 开头=mock，非 mock 有效字符串=live；metadata 缺失/非法/worker down=unknown。仅当全部已启用模型 ready 且来源一致返回 mock/live；混合或部分不可判定返回 unknown（`mixed`/`reason` 说明），不因可达/进程存活报 live。`cached` 仅由前端快照成功加载后标注。

## 5. 新增：离线基准（B8）

## 10. 阶段 2A：批量分类（2026-10-23）

新增 `POST /api/v1/classify/batch`（多条标题 × 单模型）：
- 请求 `{model, batch_id?, items:[{item_id,title}]}`；1–100 条、每条 trim 后 ≤200 code point、总计 ≤20,000 code point；
- `llm` 在 worker 调用前拒绝（400 `BATCH_LLM_NOT_ALLOWED`）；
- 空 items、超条数/总字符、空标题、非法/重复 item_id、非法模型等整批 4xx，不调用 worker；
- 成功/部分成功/全失败均为 200：`summary.status=ok|partial|all_failed`；`results` 按输入顺序，逐项 `item_id/index/status`；失败项带稳定 `error`；
- 批总时限默认 30,000ms（`TMF_BATCH_TOTAL_TIMEOUT_MS`），进程级 `TMF_BATCH_CONCURRENCY` 默认 2；不自动重试；
- **不返回 `human_feedback_hint`**；日志不记录标题；
- 前端多条输入（2B）与文件导入（3A/3B）已实现并交付（F17/F18/F19）；详见 `docs/前端对接说明.md` §10.8/§10.9。

## 11. 阶段 4B/5B：LLM 配额错误与访问名额 API（2026-10-24～25）

### 11.1 LLM 每 IP 配额（阶段 4B/4C，已接入）

- 每个客户端 IP 最多 **3 次**网关 LLM adapter 调用；额度在真正调用 `LlmAdapter` 前原子 reserve，超时/Provider 错误/无效输出均不退款。
- 第 4 次及以后：HTTP **403 `LLM_QUOTA_EXHAUSTED`**，`details` 可含 `limit=3`/`used=3`；本地模型不受影响，前端不得当作 `WORKER_UNAVAILABLE`。
- quota store 配置/初始化/读写失败：HTTP **503 `LLM_QUOTA_UNAVAILABLE`**（fail-closed，LLM 不可用，本地模型语义不变）。
- 无有效客户端身份：HTTP **403 `LLM_QUOTA_IDENTITY_INVALID`**；这是 fail-closed，不猜测 IP。
- `/compare`、`/compare/stream` 显式包含 LLM 且已耗尽时，在 fanout/创建 model task 前整请求返回 403/503，前端不要期望拿到本地模型结果。
- `/arena/next` 默认只召集 **4 个本地模型**（`rf/fasttext/bert/distill`），LLM 不参与、不消耗配额；候选/匿名揭晓/Elo 契约不变。
- `/classify/batch` 仍拒绝 LLM（400 `BATCH_LLM_NOT_ALLOWED`），**不消耗配额**。
- 离线运维 CLI：`serving/scripts/manage_llm_quota.py`（查看/重置配额，不启动服务）；生产进程需 `TMF_LLM_QUOTA_HMAC_KEY`（≥32 字节，只注入环境，不写入仓库/日志）。

### 11.2 访问名额控制（阶段 5B/5C/5D，默认关闭）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/access/enter` | 请求进入；返回 `active/ready/queued/cooling`、ticket、position/ahead、remaining_seconds；queue full 返回 429 |
| POST | `/api/v1/access/claim` | ready → active（前端自动 claim，后端幂等） |
| POST | `/api/v1/access/leave` | 主动离开 active，进入 cooling |
| POST | `/api/v1/access/cancel` | 取消排队（queued） |
| GET | `/api/v1/access/status` | 只读状态；不返回 ticket、不续期 |

- ticket 只通过请求头 **`X-Access-Ticket`** 传递，不进入 URL/日志/错误文案；服务端按 ticket + 可信 IP 绑定，前端存储不是安全边界。
- 名额与时间：**10 个 active/ready 唯一 IP**、**50 个 queued**；ready 须在 **15s** 内 claim，active **180s**（从 claim 起算），queued **120s**，到期进入 **60s** cooling（冷却不进队列）。
- 错误码：`ACCESS_REQUIRED`（403，无 ticket）、`ACCESS_CLAIM_REQUIRED`（409，ready 未 claim）、`ACCESS_QUEUED`（429）、`ACCESS_COOLING`（429）、`ACCESS_TICKET_INVALID`（403，无效/过期/重启后旧 ticket）、`ACCESS_QUEUE_FULL`（429）、`ACCESS_POLL_THROTTLED`（429，轮询过快，按 `Retry-After` 退避）、`ACCESS_DISABLED`（404，功能关闭，前端走旧流程）、`ACCESS_UNAVAILABLE`（503，manager 故障，fail-closed）。
- CORS 允许请求头增加 `X-Access-Ticket`（`allow_headers` 含 `ACCESS_TICKET_HEADER`）；`Retry-After` 需在暴露响应头中，供排队/冷却/轮询退避读取。
- access/health/OPTIONS 免业务门禁；功能开关 `TMF_ACCESS_CONTROL_ENABLED` 默认 false，启用配置必须来自启动网关的进程/用户环境，重启网关后生效。
- **access 开启时 SSE 不接入**：浏览器 `EventSource` 不能自定义 `X-Access-Ticket`，`/compare/stream` 不可用，模型对比走带 ticket 的 `POST /compare` fallback；access 关闭时 SSE 保持原行为。
- 状态为**单 Uvicorn 进程内存**，重启清空；访问管理不重置/绕过 LLM quota；生产需保持单进程（`stage2.ps1` 不带 `--workers`）。
- 本轮验收（2026-10-25 隔离复跑）：`verify_access_state.py` 90 checks PASS、`verify_access_gateway.py` 80 checks PASS、`verify_llm_quota_gateway.py` 59 checks PASS、`verify_llm_quota_cli.py` 59 checks PASS、`verify_llm_quota_infra.py` RESULT PASS。
- 未验收：真实网关在 `TMF_ACCESS_CONTROL_ENABLED=true` 下的启用、真实 LAN/手机/CORS 预检、真实 180/60/120s 等待与多标签并发 claim/leave。
