# 并发与超时契约

> 状态：2026-10-25；B6/B12 与阶段 2A 批量、4B LLM 配额、5B/5C 访问名额契约均已实现并验证；本文件不扩展这些阶段之外的调优承诺。

## 1. 单模型 `/classify`

- 每请求 1 个模型；超时取该 worker 配置（普通 10s，LLM 15s；API client 单模型 20s）。
- 前端 AbortSignal 只影响前端渲染；网关不保证中止已开始的 worker 推理。
- 失败：502/504 + 稳定错误码；不返回伪造分数/类别。

## 2. `/compare`（一次性 POST）

- 保留旧接口，一次返回 JSON；并发上限由 `TMF_COMPARE_CONCURRENCY`（默认 **3**，范围 1–10）控制。
- 单模型失败只影响该项；其余成功项仍返回，`summary.status` 为 `partial`/`all_failed`。
- **POST 不应用** `TMF_COMPARE_TOTAL_TIMEOUT_MS`；总截止仅用于 SSE（见下）。

## 2.1 `/classify/batch`（阶段 2A）

- 端点：`POST /api/v1/classify/batch`；多条标题 × **单模型**，不是 compare 的“单标题 × 多模型”。
- 预检：1–100 条、每条 trim 后 ≤200 code point、总计 ≤20,000 code point；任一不合法整批 4xx，**不调用 worker**；`llm` 在 worker 调用前拒绝。
- 逐条复用 `ClassificationService.classify`（含 worker 超时、data_source、scores/top_k/reject）；单项 worker 失败只影响该项，成功项保留；`summary.status=ok|partial|all_failed`。
- 批次总时限默认 **30,000ms**（`TMF_BATCH_TOTAL_TIMEOUT_MS`）；到点取消网关侧未完成 task，已完成结果保留，未完成项标 `BATCH_TOTAL_TIMEOUT`；客户端断开时停止后续调度，已发给 worker 的同步推理不保证中止。
- 并发：进程级共享 `asyncio.Semaphore`，上限 `TMF_BATCH_CONCURRENCY` 默认 **2**；多个批量请求共享该上限，不按 HTTP 请求各建一把；只创建 `min(concurrency, total)` 个 worker task。
- 不自动重试；单条客户端超时仍为 20s，批量客户端超时应大于服务端 30s。
- 不返回 `human_feedback_hint`，避免 N 条触发 N 次相似反馈扫描；日志不记录标题。

## 2.2 LLM 每 IP 配额（阶段 4B）

- 每个客户端 IP 最多 3 次网关 LLM adapter 调用；在真正调用 `LlmAdapter` 前原子 reserve，超时/Provider 错误/无效输出均不退款。
- `/classify`：LLM 第 4 次返回 403 `LLM_QUOTA_EXHAUSTED`；store 不可用返回 503 `LLM_QUOTA_UNAVAILABLE`，均不调用 worker。
- `/compare`、`/compare/stream` 显式含 LLM：在 fanout/创建任何 model task 前只读预检；已耗尽或 store 不可用整请求返回 403/503，不启动本地模型。
- 预检不消耗额度；预检通过后并发抢最后额度时，adapter 的原子 reserve 仍只允许 3 次。POST 的 LLM 项可返回 `status=error`（响应 200 partial），SSE 以该模型的 `model` 事件错误表达；其他已启动本地模型正常收尾。
- `/arena/next` 默认只召集 4 个本地模型，不触发 LLM、不消耗配额；`/classify/batch` 仍拒绝 LLM、不扣配额。
- 严格可信来源边界：`stage2.ps1` 已用 Uvicorn `--no-proxy-headers` 关闭默认代理头信任；`client_ip.py` 只在显式 `TMF_TRUSTED_PROXY_CIDRS` 下解析转发头。详见 `serving/README.md`。

## 2.3 访问名额/队列/租约（阶段 5B/5C）

- `TMF_ACCESS_CONTROL_ENABLED` 默认 false；启用后，除 access/health/OPTIONS 外的业务 API 必须带当前可信 IP 的 active `X-Access-Ticket`。
- 10 个 active/ready 唯一 IP；FIFO 最多 50 个 queued IP；queue full 返回 429 `ACCESS_QUEUE_FULL`。
- ready 15s claim；active 固定 180s，从 claim 起算；queued 120s；active 到期进入 60s cooling，冷却不进队列。
- gate 只检查，不续期；queued -> 429 `ACCESS_QUEUED`，ready -> 409 `ACCESS_CLAIM_REQUIRED`，cooling -> 429 `ACCESS_COOLING`，无效/过期 -> 403 `ACCESS_TICKET_INVALID`，manager 异常 -> 503 `ACCESS_UNAVAILABLE`。
- 状态轮询默认每 IP 最小间隔 1s；前端目标 2s + jitter。access API 无需业务 ticket（除 status/claim/leave/cancel 需要 ticket 本身）。
- access 启用时前端不建立 EventSource（浏览器不能给 SSE 加 `X-Access-Ticket`），compare 走受 gate 保护的 `POST /compare` fallback；access 关闭时 SSE 原行为不变。后台仍在 `StreamingResponse` 前 gate，active 剩余租约限制流生命周期，到期用 `ACCESS_EXPIRED` error 事件关闭。
- 单 Uvicorn 进程内存；重启清空状态。访问管理不重置/绕过 LLM quota。

## 3. `/compare/stream`（SSE）

- 端点：`GET /api/v1/compare/stream?title=...&models=a,b,c`（query，EventSource 兼容）。
- 事件：
  - `model`：`request_id/model_id/status/latency_ms/model_version/pred_class/error/data_source`，每模型最多一次，按实际完成顺序；
  - `summary`：`request_id/status/total/ok/failed/elapsed_ms/total_timeout_ms/partial`；
  - `done`：summary 后紧接一次，随后关闭；
  - `error`：仅请求/流级致命错误；逐模型失败用 `model.status=error`。
- 心跳：`: heartbeat` 注释，每 15s；不是事件，不延长截止。
- 总截止：`TMF_COMPARE_TOTAL_TIMEOUT_MS`，默认 **18000ms**（范围 100–300000）；到点取消未完成网关 task，保留已完成项，summary/done 标 `partial`（无成功则 `all_failed`）。
- 客户端断开：停止 push，取消/收尾网关 task；已开始的 worker 请求按本期限制不强制中止。
- 并发：与 POST 共用 `TMF_COMPARE_CONCURRENCY`，没有第二套并发/截止配置。

## 4. Worker 线程与推理锁

- BERT/蒸馏：`TMF_TORCH_THREADS` 默认 **4**（范围 1–64），在模型加载前 `torch.set_num_threads`。
- 两个 worker 进程内用 `threading.Lock` 串行推理；不同 worker 是不同进程，锁互不影响。
- 真实负载证据：BERT/蒸馏并发 1/3/5 隔离测量；最大活跃推理数均为 1；细节见 `artifacts/b12/real_concurrency_2026-10-22.json`。
- 当前 PyTorch interop 线程默认 8，CPU% 可超过 100%；这是进程多线程统计，不代表同一 worker 推理并行进入临界区。

## 5. 实时输入（F5）

- 250ms debounce；每输入 abort 旧请求；单调 seq 只接受最新；最短 4 字、最多 200 字；IME composition 期间不请求；失败静默。
