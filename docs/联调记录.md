接口契约（5 个模块统一）：


## 三、本轮发现并修复的问题

| # | 问题 | 处理 |
|---|---|---|
| 1 | **fastText 与 numpy 2.x 不兼容**（`np.array(x, copy=False)` → `ValueError`） | 新增 `tools/patch_fasttext_numpy2.py`（幂等、自动备份，替换 5 处为 `np.asarray`），实测 `predict`/`test` 恢复（test P@1=0.9173） |
| 2 | **`01-rf` / `03-bert` / `05-distill` 缺 `title` 时抛 KeyError → 500 HTML** | 三个 `*_predict_service.py` 增加入参兜底，统一返回结构化 JSON error |
| 3 | **Flask `debug=True` 的 reloader 子进程残留、占住端口** | 5 个 `api_flask_server.py` 全部改为 `debug=False`；联调后端口全部释放 |
| 4 | **LLM key 失效**（Qwen/智谱 401）+ 服务默认走 Qwen | 改用 DeepSeek（新 key 实测可用），`llm_predict_service.py` 重写：`.env` 绝对路径、平台可切换（`TMF_LLM_PROVIDER`）、`temperature=0`、**输出白名单校验 + 非法重试一次** |
| 5 | **fastText 在 conda 环境里因 numpy 2 不可用** | 优先用 `tools/patch_fasttext_numpy2.py`；全新环境仍建议按 `requirements.txt` 装 `numpy<2` |
| 6 | 5 个模块端口/契约不一致（历史问题） | 已统一为 8101/8103/8104/8105/8106 + `/predict_api` + 字段 `title`（骨架阶段完成） |

## 四、环境限制与对策（重要）

- **`D:\Miniconda3\envs\py3109\Scripts` 目录只有管理员有写权限**（当前进程未提权，`icacls` 也无法修改），
  因此 `pip install` 任何带命令行脚本的包（flask/streamlit/matplotlib/numpy 的 f2py 等）都会在写 exe 时失败。
  - numpy 被卸载后通过「下载 wheel → 解包回 site-packages」恢复（site-packages 可写）；
  - streamlit 无法装进该环境，前端测试改用另一个可写环境（streamlit 1.61.1）；
  - **建议**：要么用管理员权限跑一次 pip 修复 Scripts 权限，要么把本工程环境换成可写的 venv
    （`python -m venv`，完全由当前用户拥有）。
- LLM key 已写入 `04-LLM/.env`（已在 `.gitignore` 中）；由于该 key 在对话中出现过，**演示结束后建议到 DeepSeek 控制台轮换**。
- 本轮联调期间蒸馏 v2 仍在后台训练，CPU 竞争导致部分首请求延迟偏高（BERT 首请求 64s）；
  单独运行时热请求 BERT 约 90~130ms。

## 五、复现方式

```powershell
# 1) 修 fastText 的 numpy2 兼容（若环境里 numpy 是 2.x）
python tools/patch_fasttext_numpy2.py

# 2) 起某个模块的后端（示例：BERT，端口 8104）
cd 03-bert; python api_flask_server.py
# 3) 起对应前端
cd 03-bert; python run_streamlit.py        # 浏览器打开 http://localhost:8501
# 4) 或用 curl 验证
curl -X POST http://127.0.0.1:8104/predict_api -H "Content-Type: application/json" -d "{\"title\":\"北京二手房成交量创年内新高\"}"
```
