## 2. 三档断点检查

| 断点 | 视口 | 横向滚动检查 | 结果 |
|---|---|---|---|
| ≤640px | 390px | `scrollWidth=390, clientWidth=390` | 通过 |
| ≤640px | 640px | `scrollWidth=640, clientWidth=640` | 通过 |
| 641–1024px | 768px | `scrollWidth=768, clientWidth=768` | 通过 |
| 641–1024px | 1024px | `scrollWidth=1024, clientWidth=1024` | 通过 |
| >1024px | 1280px | `scrollWidth=1280, clientWidth=1280` | 通过 |
| >1024px | 1920px | `scrollWidth=1920, clientWidth=1920` | 通过 |

判定标准：`document.documentElement.scrollWidth <= clientWidth` 且 `document.body.scrollWidth <= clientWidth`。

## 3. 暗色主题与对比度

| 检查项 | 证据/结果 |
|---|---|
| 初始主题跟随 `prefers-color-scheme` | 通过 CDP `Emulation.setEmulatedMedia` 设置 dark 后，首屏 `data-theme=dark`、`localStorage` 为空；设置 light 手动后刷新保持 light |
| 手动切换 | 点击 NavBar“暗色/亮色”按钮，`data-theme` 在 light/dark 间切换 |
| 刷新保留 | 手动切暗后刷新，`data-theme=dark` 保持；`localStorage['tmf.theme']='dark'` |
| 正文对比度 | 暗色下 `.hero-description` / `.section-heading > p` / `.footer`：`rgb(167,178,194)` on `rgb(15,20,32)` = **8.58:1**；导航 `#fff` on 页背景 = **16.69:1** |
| 暗色组件覆盖 | 卡片、输入框、导航、模型选择、结果卡、反馈条、footer 使用暗色 token/主题收敛层 |

> 对比度按 WCAG 相对亮度公式计算；测量值见 `artifacts/f13/f13-checks.json`。
> 暗色为人工/自动主题，不改变任何数据来源或模型结果。

## 4. 大屏模式

| 检查项 | 结果 |
|---|---|
| 点击“大屏”按钮 | `data-presentation=large` |
| 字号放大 | `.site-shell` computed `zoom: 1.25`（约 1.25 倍） |
| 隐藏调试信息 | `.result-request`/`.debug-only` 在 large 下 `display:none` |
| 全屏被拒 | 注入 `requestFullscreen` reject，未出现未捕获异常，大屏布局仍可用 |
| 退出大屏 | 点击“退出大屏”，`data-presentation=normal` |
| 浏览器不支持全屏 | 代码分支保留提示，不报错；无真实不支持浏览器设备，未实测 |

## 6. D4 现场复测建议

1. 在 1920×1080 笔记本以 100%/125% 各打开一次，按本清单第 1/2 行打勾；
2. 在 1280×720 投影上检查标题、类别、延迟数字可读，补真实截图；
3. 在一台手机（建议 390px 宽度附近）检查无横向滚动、导航折叠、输入框可用；
4. 打开暗色与手动切换，刷新确认持久化；在真实设备上重新测量对比度；
5. 大屏模式点击后确认全屏请求与布局；若浏览器拒绝全屏，记录提示并确认页面仍可操作。
