## 1. 跨域（CORS）

网关只放行配置中显式声明的前端来源（默认由 `TMF_FRONTEND_HOST` / `TMF_FRONTEND_PORT` 推导）：

| 项 | 值 |
|---|---|
| 允许来源 | 默认 `http://127.0.0.1:5173`；可用 `TMF_FRONTEND_*` 或 `TMF_CORS_ORIGINS` 覆盖/追加 |
| 允许方法 | `GET`、`POST`、`OPTIONS` |
| 允许请求头 | `Content-Type`、`X-Request-ID`、`X-Access-Ticket` |
| 暴露响应头 | `X-Request-ID`、`Retry-After` |
| credentials | 不启用（`allow_credentials=False`） |

- 默认不允许 `*`，其他来源不会被浏览器放行（预检返回 400，实际请求不带 `Access-Control-Allow-Origin`）。
- 预检响应中还会出现 `Accept` / `Accept-Language` / `Content-Language`：这是 Starlette 自动加入的 CORS 安全列表头，不属于额外开放配置。
- access 启用时所有业务请求都要带 `X-Access-Ticket`，因此该头必须在允许请求头中（`serving/gateway/main.py` 的 `allow_headers=["Content-Type","X-Request-ID", ACCESS_TICKET_HEADER]`）；`Retry-After` 需暴露给浏览器，供排队/冷却与 `ACCESS_POLL_THROTTLED` 退避读取（`expose_headers=["X-Request-ID","Retry-After"]`）。
- 如前端开发端口不同，由后端在启动前设置环境变量追加来源（逗号分隔，必须明确 `http(s)://`，不允许 `*`）：
  `TMF_CORS_ORIGINS=http://127.0.0.1:5174`
  局域网则使用实际网卡来源（如 `http://<LAN_IP>:5173`）。修改后需重启网关。
- 该配置仅用于本地开发，不是生产安全方案；生产鉴权/HTTPS/反向代理不在当前范围。

## 3. 单模型分类

`POST /api/v1/classify`

请求：

```json
{"title": "北京二手房成交量创年内新高", "model": "bert"}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 是 | 去除首尾空白后非空，最多 200 个 Unicode 字符 |
| `model` | 否 | 缺省使用默认模型 `fasttext`；必须是已启用模型 ID |

成功 200：

```json
{
  "request_id": "4b8e...",
  "model_id": "bert",
  "model_version": null,
  "pred_class": "realty",
  "latency_ms": 70
}
```

- `latency_ms` 是网关调用 worker 的耗时，不是浏览器到网关的完整耗时。
- B1 起返回未校准 `scores`/`score_kind`/`top_k`（分数不是 calibrated confidence）；B3 另返回 `rejected/reject_reason/threshold_meta`；前端必须标“未校准”，无分数时显示“该模型不提供可信度”。
- 未知模型 → 404 `UNKNOWN_MODEL`；禁用模型 → 400 `MODEL_DISABLED`。

## 4. 多模型比较

`POST /api/v1/compare`

请求（默认比较 4 个本地模型；LLM 需显式列入 `models`）：

```json
{"title": "北京二手房成交量创年内新高"}
```

或显式指定模型（结果顺序按请求顺序）：

```json
{"title": "北京二手房成交量创年内新高", "models": ["fasttext", "bert"]}
```

成功/部分成功均为 HTTP 200：

```json
{
  "request_id": "4b8e...",
  "summary": {"total": 4, "ok": 3, "failed": 1, "status": "partial"},
  "results": [
    {"model_id": "rf", "status": "ok", "latency_ms": 82,
     "model_version": null, "pred_class": "realty"},
    {"model_id": "llm", "status": "error", "latency_ms": 15000,
     "error": {"code": "WORKER_TIMEOUT", "message": "所选模型未在配置的时间内返回"}}
  ]
}
```

规则：

- 默认顺序：`rf, fasttext, bert, distill`（配置顺序，仅本地模型）；`llm` 只会在显式 `models` 中出现。
- 注意：`llm` 是 **opt-in**，默认 compare 不包含它；Vue 前端需用户显式开启。
- `summary.status` 只可能是 `ok`、`partial`、`all_failed`。
- 合法请求即使全部模型失败也返回 HTTP 200；失败项**没有** `pred_class`，不要显示为空类别。
- 空 `models`、重复模型 ID → 400 `INVALID_MODELS`；未知模型 → 404 `UNKNOWN_MODEL`；这些情况不会调用任何 worker。
- 单个模型失败不会取消其他模型结果。

## 5. Request ID

- 可选请求头：`X-Request-ID`，格式 `^[A-Za-z0-9._-]{1,64}$`。
- 不传时网关生成 UUID；响应头与响应体的 `request_id` 一致。
- 格式非法 → 400 `INVALID_REQUEST_ID`。
- 浏览器可通过 CORS 暴露的 `X-Request-ID` 响应头读取该值，用于日志对照。

## 6. 错误结构与建议行为

统一错误体：

```json
{
  "request_id": "4b8e...",
  "error": {
    "code": "WORKER_TIMEOUT",
    "message": "所选模型未在配置的时间内返回",
    "details": {"model_id": "llm"}
  }
}
```

| HTTP | code | 前端建议 |
|---|---|---|
| 400 | `INVALID_TITLE` | 提示用户输入标题 |
| 400 | `TITLE_TOO_LONG` | 提示最多 200 字符 |
| 400 | `MODEL_DISABLED` | 从模型列表刷新启用状态 |
| 400 | `INVALID_MODELS` | 检查 `models` 是否为空/重复 |
| 400 | `INVALID_REQUEST_ID` | 检查 `X-Request-ID` 格式 |
| 404 | `UNKNOWN_MODEL` | 刷新 `/models`，不要硬编码模型 ID |
| 422 | `INVALID_REQUEST` | 检查 JSON 字段类型/必填 |
| 502 | `WORKER_UNAVAILABLE` / `WORKER_HTTP_ERROR` / `WORKER_BAD_RESPONSE` / `MODEL_ERROR` / `INVALID_MODEL_OUTPUT` | 展示逐模型失败；可提示稍后重试 |
| 504 | `WORKER_TIMEOUT` | 展示超时；可减少并发或稍后重试 |
| 500 | `INTERNAL_ERROR` | 提示服务异常；不要展示堆栈 |

- 分类/比较是只读操作；前端可对 502/504 做有限次数重试（建议 ≤1 次），不要无限重试。**当前 Vue 实现未做自动重试**（失败后由用户手动重新提交或"重新连接"）。
- 错误响应不含标题、密钥、Authorization、完整堆栈或供应商原始错误文本。

### 10.7 批量分类（阶段 2A，后端）
`POST /api/v1/classify/batch`

请求：
```json
{
  "model": "fasttext",
  "batch_id": "paste-20261023-001",
  "items": [
    {"item_id": "r000001", "title": "北京二手房成交量创年内新高"},
    {"item_id": "r000002", "title": "Zacks调升苹果目标股价至200美元"}
  ]
}
```

- 整批共用一个 `model`；`llm` 在调用 worker 前返回 400 `BATCH_LLM_NOT_ALLOWED`。
- `items` 为 1–100 条；每条 `item_id` 唯一、格式 `^[A-Za-z0-9._-]{1,64}$`；每条 title trim 后 1–200 个 Unicode code point；总计 ≤20,000 个 code point。
- 空 items、101 条、单条超长、空标题、非法/重复 item_id、总字符超限、未知/禁用模型：整批 4xx，**不调用任何 worker**。
- 成功/部分成功/全部失败均为 HTTP 200：`summary.status=ok|partial|all_failed`；`results` 严格按输入顺序，包含 `item_id/index/status`；成功项含 `pred_class/latency_ms/model_version/data_source` 及可用的 `scores/top_k/rejected` 等字段；失败项只带稳定 `error`。
- 批次 `request_id` 为顶层字段；每条结果用 `item_id/index` 映射，不单独返回 per-item request_id。
- **不返回 `human_feedback_hint`**，避免批量触发 N 次相似反馈扫描。
- 批次总时限默认 30,000ms；未完成项返回 `BATCH_TOTAL_TIMEOUT`；客户端断开返回 `BATCH_CANCELLED`（若仍可返回）。
- 批量并发为进程级 `TMF_BATCH_CONCURRENCY`（默认 2），不是 compare 的 `TMF_COMPARE_CONCURRENCY`；不做自动重试。
- 限制可用 `TMF_BATCH_MAX_ITEMS` / `TMF_BATCH_MAX_TOTAL_CHARS` 收紧。

### 10.8 前端多条输入（阶段 2B）
- “单模型分类”内提供“单条标题 / 多条标题”切换；模型对比仍是单标题 × 多模型，不显示多条开关。
- 多条模式：统一 CRLF/CR/LF 后按行拆分、每行 trim、空行忽略；一行一条；重复标题保留并提示；显示原始行号、预览、逐条字符数、总条数和总字符数。
- 前端按 Unicode code point（`Array.from(text).length`）计数，与 Python `len()` 对齐；单条 >200、总条数 >100、总字符 >20,000 时阻止提交，不发送请求。
- 每 10 条串行调用一次 `POST /api/v1/classify/batch`，`batch_id` 关联同一用户批次，`item_id` 由原始行号生成（如 `r000001`）；客户端批量超时 35s（服务端 30s）。
- LLM 在多条模式中不可选，界面明确说明 v1 批量不支持大模型；服务端仍会最终拒绝 `llm`。
- 结果按输入顺序展示；分片失败/取消时保留已完成结果；失败项可单独重试，不自动重试；批量结果不展示 `human_feedback_hint`。

### 10.9 前端 TXT/CSV 文件导入（阶段 3B）
- 文件入口只在“单模型分类 → 多条标题”显示；支持 `.txt` / `.csv`（扩展名不区分大小写），最大 1 MiB；先检查 `File.size`，超限不调用 `arrayBuffer()`。
- 文件只在浏览器本地读取、解码、解析和预览；**不上传文件字节，不把文件或标题写入服务器**。只有用户确认导入后，规范化标题才进入现有批量分类 JSON。
- 编码：UTF-8、UTF-8 BOM；严格 UTF-8 失败后回退 GB18030；不支持 UTF-16。预览显示检测编码和 BOM 状态。
- TXT：一行一条，统一 CRLF/CR/LF，trim 首尾、空行跳过并统计、重复保留、Tab 后标签不剥离；预览显示物理行号、标题、code point 长度。
- CSV：v1 仅逗号；使用 RFC4180 基本解析（引号字段、`""`、引号内逗号和换行）。预览显示数据记录号/物理起始行号。
- CSV 表头：命中候选列名自动识别；无法识别时要求用户明确选择“首行是表头/首行是数据”，未确认不能导入。
- CSV 标题列：单列自动选择；多个候选列必须选择；无候选列默认第一列但需用户勾选确认；未确认不能导入。
- 坏行：字段数不一致或可恢复引号错误默认阻止导入；用户勾选“跳过错误行”后才跳过并显示跳过数量。编码、整体结构、超限错误不能跳过。
- 上限：有效标题最多 100 条、总字符最多 20,000、单条最多 200 code point；超限阻止导入，不自动分批、不截断。
- 已有手动草稿/结果时，导入前必须选择“替换”或“取消”，默认焦点在取消；取消不改动任何草稿/结果/进度。替换保留手动草稿，清除文件导入后可恢复。
- 导入后标题列表只读；用户需清除导入返回文本模式。文件来源行号/记录号保留到批量结果行。
- 后续分片失败时，未开始分片保持“未提交”；“重试失败项”只发送有 `error` 的条目，不重新发送成功项；若仍存在未提交项，批次保持 partial 而不是伪装为全部完成。
- 实现文件：`frontend/src/utils/titleFiles.ts`（解析纯函数）、`FileImportPanel.vue`/`ImportedBatchPreview.vue`、`useBatchClassify.ts`（文件来源支持）；验收为 `frontend/tests/f19/`（浏览器内存 File + mock API）。

### 10.10 阶段 4B：LLM 配额错误（后端已接入，前端需按错误码展示）
- 每个客户端 IP 最多 3 次网关 LLM adapter 调用；第 4 次及以后返回 HTTP **403**，稳定错误码 **`LLM_QUOTA_EXHAUSTED`**，`details` 可含 `limit=3`/`used=3`；本地模型仍可用，前端不应把它当作 `WORKER_UNAVAILABLE`。
- quota store 配置/初始化/读写失败返回 HTTP **503**，稳定错误码 **`LLM_QUOTA_UNAVAILABLE`**；此时 LLM 不可用，其他本地模型按原语义。
- 无有效客户端身份返回 HTTP **403 `LLM_QUOTA_IDENTITY_INVALID`**；这是 fail-closed，不猜测 IP。
- `/compare`、`/compare/stream` 显式包含 LLM 且已耗尽时，在 fanout 前整请求返回 403/503；前端不要期望拿到本地模型结果。并发抢到最后额度时，SSE 可能以 `model` 事件中的 `LLM_QUOTA_EXHAUSTED` 表达逐项失败，其他本地模型仍正常收尾。
- `/classify/batch` 仍拒绝 LLM（400 `BATCH_LLM_NOT_ALLOWED`），不消耗配额。
- `/arena/next` 默认只召集 4 个本地模型（`rf/fasttext/bert/distill`），LLM 不参与、不消耗配额；候选/匿名揭晓/Elo 契约不变。
- 运维前提：生产进程需设置 `TMF_LLM_QUOTA_HMAC_KEY`（≥32 字节、随机、安全保存）；`stage2.ps1` 已使用 Uvicorn `--no-proxy-headers` 关闭默认代理头信任，`client_ip.py` 是唯一信任边界。详见 `serving/README.md` 阶段 4B 收口说明。

### 10.11 阶段 5B/5C：访问名额 API、业务门禁与前端交互（已接入）
- 功能开关 `TMF_ACCESS_CONTROL_ENABLED` 默认 false；启用需操作员显式设置并重启网关。前端不打开开关；启动时通过 `enter` 探测，404 `ACCESS_DISABLED` 自动走旧流程。
- **启用环境**：启动脚本不会从 `.env` 加载访问控制配置；`TMF_ACCESS_CONTROL_ENABLED` 与 `TMF_LLM_QUOTA_HMAC_KEY` 必须在启动网关的同一 PowerShell/CMD 环境（或用户环境）中存在，重启网关后才生效。`stage2.ps1` 会读取 `04-LLM/.env` 中的 `DEEPSEEK_API_KEY`，仅用于判断是否启动 LLM worker，不会把 access 配置加载到网关。完整生成、检查、验证和回滚步骤见根 `README.md`「访问名额控制」；不要把 key 写入前端、URL、日志或仓库。
- API：`POST /api/v1/access/enter`、`GET /api/v1/access/status`、`POST /api/v1/access/claim`、`POST /api/v1/access/leave`、`POST /api/v1/access/cancel`；ticket 只通过 `X-Access-Ticket` 请求头传递。
- `enter` 返回 `active/ready/queued/cooling`、ticket、position/ahead、remaining_seconds；`queue_full` 返回 429 `ACCESS_QUEUE_FULL`。`status` 不返回 ticket，也不续期。
- 业务门禁：无 ticket 403 `ACCESS_REQUIRED`；queued 429 `ACCESS_QUEUED`；ready 409 `ACCESS_CLAIM_REQUIRED`；cooling 429 `ACCESS_COOLING`；token 无效/过期 403 `ACCESS_TICKET_INVALID`；manager 故障 503 `ACCESS_UNAVAILABLE`。
- 全局访问状态由 `useAccess` 持有：启动 enter；ready 自动 claim；active 显示倒计时和提前离开；queued 显示 position/ahead 并可取消；cooling 显示冷却倒计时；queue_full 只提供手动重试；expired/无效 ticket/服务重启清理旧 ticket 并重新 enter；`ACCESS_UNAVAILABLE`/身份错误 fail-closed，不加载业务页面。
- ticket 使用 `localStorage`（不可用时 sessionStorage/内存）保存 opaque 值，支持刷新恢复和同源标签共享；不保存 IP，不进入 URL/日志/错误文案/遥测。服务端仍负责 ticket + IP 绑定，前端存储不是安全边界。
- 轮询约 2s + jitter，页面隐藏约 8s；`ACCESS_POLL_THROTTLED` 按 Retry-After/合理的 1.5–2s 退避，不视为致命错误。倒计时只展示，服务端 TTL 是唯一权威；不续租。
- 关闭/回滚：在同一环境把 `TMF_ACCESS_CONTROL_ENABLED` 设为 false 并重启网关；旧 ticket/内存队列/冷却失效，建议刷新前端。不要删除 quota SQLite，也不要因回滚随意轮换共用 key。
- 同源标签通过 `storage` 事件同步；其他标签 leave/清空后，本标签进入恢复流程。重复 claim 由后端幂等处理，前端用 in-flight/generation 防止并行和旧响应覆盖。
- 业务 API client 自动注入 ticket；access API 不自动复用旧 ticket，仅显式带自身 ticket。
- **SSE 限制**：浏览器 `EventSource` 不能自定义 `X-Access-Ticket`，后端也没有可安全替代的 ticket 传递方式；access 启用时不建立 SSE 连接，`/compare/stream` 不接入，模型对比走受同一门禁保护的 `POST /compare` fallback（自动带 ticket）。access 关闭时 SSE 保持原行为。没有把 ticket 放入 URL，也没有修改后端契约。
- access/health/OPTIONS 免业务门禁；静态页面可打开，但未 active 时业务内容不挂载、不调用业务 API。390px 下排队/冷却/倒计时/取消界面可读可操作。
- 验收：`frontend/tests/f20/`（真实 App + 本地 mock access/业务 API + Edge headless）；前端 `type-check` 通过。F20 于 2026-10-25 记录 58 checks PASS；OCR/微博热搜导航断言已纳入。
