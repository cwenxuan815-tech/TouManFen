## 1. 跨域（CORS）

网关只放行配置中显式声明的前端来源（默认由 `TMF_FRONTEND_HOST` / `TMF_FRONTEND_PORT` 推导）：

| 项 | 值 |
|---|---|
| 允许来源 | 默认 `http://127.0.0.1:5173`；可用 `TMF_FRONTEND_*` 或 `TMF_CORS_ORIGINS` 覆盖/追加 |
| 允许方法 | `GET`、`POST`、`OPTIONS` |
| 允许请求头 | `Content-Type`、`X-Request-ID` |
| 暴露响应头 | `X-Request-ID` |
| credentials | 不启用（`allow_credentials=False`） |

- 默认不允许 `*`，其他来源不会被浏览器放行（预检返回 400，实际请求不带 `Access-Control-Allow-Origin`）。
- 预检响应中还会出现 `Accept` / `Accept-Language` / `Content-Language`：这是 Starlette 自动加入的 CORS 安全列表头，不属于额外开放配置。
- 如前端开发端口不同，由后端在启动前设置环境变量追加来源（逗号分隔，必须明确 `http(s)://`，不允许 `*`）：
  `TMF_CORS_ORIGINS=http://127.0.0.1:5174`
  局域网则使用实际网卡来源（如 `http://<LAN_IP>:5173`）。修改后需重启网关。
- 该配置仅用于本地开发，不是生产安全方案；生产鉴权/HTTPS/反向代理不在当前范围。

## 3. 单模型分类

`POST /api/v1/classify`

请求：

```json
{"title": "北京二手房成交量创年内新高", "model": "bert"}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 是 | 去除首尾空白后非空，最多 200 个 Unicode 字符 |
| `model` | 否 | 缺省使用默认模型 `fasttext`；必须是已启用模型 ID |

成功 200：

```json
{
  "request_id": "4b8e...",
  "model_id": "bert",
  "model_version": null,
  "pred_class": "realty",
  "latency_ms": 70
}
```

- `latency_ms` 是网关调用 worker 的耗时，不是浏览器到网关的完整耗时。
- 不返回 `confidence`/概率；前端不要展示置信度。
- 未知模型 → 404 `UNKNOWN_MODEL`；禁用模型 → 400 `MODEL_DISABLED`。

## 4. 五模型比较

`POST /api/v1/compare`

请求（默认比较 5 个启用模型）：

```json
{"title": "北京二手房成交量创年内新高"}
```

或显式指定模型（结果顺序按请求顺序）：

```json
{"title": "北京二手房成交量创年内新高", "models": ["fasttext", "bert"]}
```

成功/部分成功均为 HTTP 200：

```json
{
  "request_id": "4b8e...",
  "summary": {"total": 5, "ok": 4, "failed": 1, "status": "partial"},
  "results": [
    {"model_id": "rf", "status": "ok", "latency_ms": 82,
     "model_version": null, "pred_class": "realty"},
    {"model_id": "llm", "status": "error", "latency_ms": 15000,
     "error": {"code": "WORKER_TIMEOUT", "message": "所选模型未在配置的时间内返回"}}
  ]
}
```

规则：

- 默认顺序：`rf, fasttext, bert, llm, distill`（配置顺序）。
- 注意：默认包含 `llm` 是 **API 层**行为；Vue 前端（`../frontend/`）默认**不**把 llm 纳入请求，需用户显式开启 opt-in。
- `summary.status` 只可能是 `ok`、`partial`、`all_failed`。
- 合法请求即使全部模型失败也返回 HTTP 200；失败项**没有** `pred_class`，不要显示为空类别。
- 空 `models`、重复模型 ID → 400 `INVALID_MODELS`；未知模型 → 404 `UNKNOWN_MODEL`；这些情况不会调用任何 worker。
- 单个模型失败不会取消其他模型结果。

## 5. Request ID

- 可选请求头：`X-Request-ID`，格式 `^[A-Za-z0-9._-]{1,64}$`。
- 不传时网关生成 UUID；响应头与响应体的 `request_id` 一致。
- 格式非法 → 400 `INVALID_REQUEST_ID`。
- 浏览器可通过 CORS 暴露的 `X-Request-ID` 响应头读取该值，用于日志对照。

## 6. 错误结构与建议行为

统一错误体：

```json
{
  "request_id": "4b8e...",
  "error": {
    "code": "WORKER_TIMEOUT",
    "message": "所选模型未在配置的时间内返回",
    "details": {"model_id": "llm"}
  }
}
```

| HTTP | code | 前端建议 |
|---|---|---|
| 400 | `INVALID_TITLE` | 提示用户输入标题 |
| 400 | `TITLE_TOO_LONG` | 提示最多 200 字符 |
| 400 | `MODEL_DISABLED` | 从模型列表刷新启用状态 |
| 400 | `INVALID_MODELS` | 检查 `models` 是否为空/重复 |
| 400 | `INVALID_REQUEST_ID` | 检查 `X-Request-ID` 格式 |
| 404 | `UNKNOWN_MODEL` | 刷新 `/models`，不要硬编码模型 ID |
| 422 | `INVALID_REQUEST` | 检查 JSON 字段类型/必填 |
| 502 | `WORKER_UNAVAILABLE` / `WORKER_HTTP_ERROR` / `WORKER_BAD_RESPONSE` / `MODEL_ERROR` / `INVALID_MODEL_OUTPUT` | 展示逐模型失败；可提示稍后重试 |
| 504 | `WORKER_TIMEOUT` | 展示超时；可减少并发或稍后重试 |
| 500 | `INTERNAL_ERROR` | 提示服务异常；不要展示堆栈 |

- 分类/比较是只读操作；前端可对 502/504 做有限次数重试（建议 ≤1 次），不要无限重试。**当前 Vue 实现未做自动重试**（失败后由用户手动重新提交或"重新连接"）。
- 错误响应不含标题、密钥、Authorization、完整堆栈或供应商原始错误文本。
