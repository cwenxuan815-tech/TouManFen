### 1.2 六个关键发现

1. **用户已完成三项重构，本期只需在其上扩展**：模型适配层（`ModelAdapter` 协议 + 两个实现 + composition root）、worker 统一契约（`PredictService` + `flask_shell` + 5 个薄壳入口）、网络配置环境变量化（源码与配置已无固定局域网 IP，README 已补文档）。全部**未提交**，本计划将其视为既有基线，不重复计价。
2. **重构同时带来一套可复用的验收资产**：`verify_refactor_gateway.py`（TestClient + 适配器错误路径 + 配置覆盖 + 无固定 IP 静态检查）与 `verify_refactor_workers.py`（契约 + 薄壳路由 + readyz 503）。这意味着 B1/B10 不必从零搭测试脚手架，只需**扩展已有脚本**——这是本版工时下调的主要依据。
3. **概率仍全链路缺失**：worker 契约 → 适配器协议 → 网关 schema → 前端 types 四层都没有该字段；`verify_stage3.py` 仍有 3 处「无 confidence」断言。因此「置信度」必须是联合任务，且**顺带要改掉这 3 条旧断言**。
4. **`/compare` 仍非流式，且没有请求级总截止**：只有 `Semaphore(5)`，最坏情况由单模型超时（LLM 15s）决定；客户端断连不会取消后端任务。逐条展示必须新增 SSE 端点。
5. **前端零竞态控制**：没有任何 `AbortController`，一旦加入「输入即预测」，旧响应晚到会覆盖新输入——本版仍必须显式立项（F5）。
6. **可降级素材已经具备**：`mock_worker.py` 的 `MOCK_SLOW` / `MOCK_*` 与 `--display-name` 足以支撑「确定性演示 + 真实性标识」，无需新造 mock 机制（B11/F15）。

## 4. 关键产品定义与待评审假设

### 4.1 四层「置信度」

| 层 | 定义 | 本期处理 |
|---|---|---|
| L1 原始分数 | `predict_proba` / softmax / fastText 概率，**未校准** | B1 透传，`score_kind` 标明来源 |
| L2 校准概率 | dev 集 temperature scaling 后的概率 | **移出本期（P2）**；因此 L1 一律显示「未校准」 |
| L3 Top-k | 按 L1 排序的前 k 类 | B1 输出（默认 3） |
| L4 业务拒识阈值 | 低于阈值提示「低置信/可能非新闻」 | B3 用合成负样本 + ROC 标定；**软拒识**，不丢弃原预测 |

**文案红线**：L2 未上线前，UI 与文档**不得**出现「模型有 X% 把握」；不得跨模型比较分数绝对值。

### 4.2 解释的定义

- 本期（F6 内）：仅展示「类别典型词」（来自该类训练集高频词）+ 方法说明，标注「相关词，非因果」。
- 移出本期（P2，原 F7）：fastText 逐词消融、RF TF-IDF 权重等词级归因。
- **不得**将「关键词与类别相关」表述为「该词导致概率上升」。

### 4.3 竞技场的评价对象与规则

| 项 | 定义 |
|---|---|
| 参赛实体 | 5 个**真实模型**；集成与 oracle 只进 PK 榜，不进竞技场 |
| 一票的含义 | 用户从 5 个匿名结果中选出「更像正确标签」的一个（**偏好判断**，不要求用户知道真值） |
| 匿名化 | **服务端**打乱并分配 `anon_id`；`model_id` 不下发直至投票后揭晓 |
| 计分 | 选中者与其余 4 个各做 1 次 Elo 更新（等效 4 组对局）；初始 1200，K=24 |
| 平局/异常 | 同一 `client_id + item_id` 只计 1 票；跳过/超时不投票；无「平票」选项（本期不做） |
| 数据性质 | Elo **只表示人类偏好强度**，不是准确率；页面须与离线榜并列、分列标注 |
| 低票数显示 | `票数 < 50` → 显示「预热中」+ Wilson 区间，不显示名次；`≥ 50` 才排序 |
| 防刷边界 | 本期只做：`client_id` 随机 UUID + 同题去重 + 单客户端每分钟 ≤ 20 票（内存计数）。**不做**验证码/IP 画像；页面注明「票数可被本机清除，仅作演示参考」 |
| 无真实投票时 | 演示者连投 5 票并说明「样本量不足，名次仅供参考」；不得伪造票数 |

### 6.2 数据流变化

```
分类：浏览器 → 网关 /classify → worker /predict_api → {pred_class, top_k, score_kind}
      → 适配器解析并校验白名单 → schema(+data_source) → 前端（有分数才画置信条）

实时输入：输入 → 250ms 防抖 → abort 上一个请求 → fastText 单模型 → 序列号校验 → 渲染

反馈：前端 /feedback → 网关写 SQLite(pending) → 相似检索命中 → 后续同类请求附「人工反馈参考（未审核）」（不改 pred_class）

对比：前端 EventSource ← 网关逐条 push（并发 ≤ N，总截止 T）← 各 worker；断连即停发

竞技场：/arena/next（匿名）→ /arena/vote（去重+限速+Elo）→ /arena/leaderboard（预热/排序）

基准：离线脚本一次运行 → artifacts/bench/pk_*.json（含 meta）→ /bench/pk 只读返回
```

### 6.6 并发、超时、取消与降级契约（本期明确定义）

| 场景 | 并发限制 | 超时 | 总截止 | 取消语义 | 失败降级 |
|---|---|---|---|---|---|
| 单模型 `/classify` | 每请求 1 个 | 该模型配置（10s / LLM 15s） | 同单模型超时 | 前端 abort → 后端**不保证**中止 worker（本期限制） | 502/504 + 错误码 |
| `/compare` | `TMF_COMPARE_CONCURRENCY`（默认 **3**，可配） | 同上 | `TMF_COMPARE_TOTAL_TIMEOUT_MS`（默认 **18000**） | 超总截止即返回已完成项 | `partial` / `all_failed` |
| `/compare/stream` | 同上 | 同上 | 同上 | 客户端断开 → 停止 push（已开始的 worker 请求不强制中断） | 逐条 `error` 事件 |
| 实时输入 | 同时最多 **1** 个在途 | fastText 10s | — | abort + 序列号丢弃 | 静默降级为「无实时结果」，不弹错 |
| 竞技场 `/arena/next` | 每请求 5 个（内部并发 3） | 同 compare | 同 compare | 超时 → 返回可投票子集或 503 | 允许部分模型缺席并标注 |

**明确写进文档的限制**（不许含糊）：
1. 网关不检测客户端断连（Starlette 层可检测但本期不实现），因此 abort 只影响前端渲染；
2. 无重试（适配器 0 次重试；LLM worker 内部最多 1 次格式重试，见 [llm_predict_service.py](../04-LLM/llm_predict_service.py)）；
3. 并发上限从 5 降到 3 的原因：单机 8 核上 BERT/蒸馏同时推理会互相抢线程（由 B12 实测确认，不达标则降到 2）。

### 6.7 演示模式与真实性契约

## 14. 验收标准

### 14.1 分级验收

| 级别 | 标准 |
|---|---|
| **接口级** | B1/B3/B4/B6/B7/B8/B11/B13 各有 ≥1 条可复现命令与断言；`verify_refactor_gateway.py`、`verify_refactor_workers.py`、`verify_stage3.py --llm-mode mock` 三者退出码均为 0 |
| **演示可重复性** | 10 步流程连续 2 次走通（1 正常 + 1 故障）；单次 ≤ 7 分钟；无人工修复 |
| **功能级** | 步骤 1–6、8–10 一次连续走通；步骤 7 允许按 D-08 降级 |
| **数据真实性** | 三态（live/mock/cached）可区分且不串味；统计不含 mock/cached；Elo 与准确率分列；离线指标带 meta |
| **竞态与负载** | 慢响应下旧结果永不覆盖新输入；连续输入 30 次在途请求 ≤1；并发 3 时无 OOM、无 `all_failed` |
| **视觉级** | 三档断点无横向滚动；暗色正文对比度 ≥ 4.5:1；缩放 125% 不破版；投影分辨率关键数字可读 |
| **交互级** | 键盘-only 完成「输入 → 提交 → 纠错 → 投票」；焦点可见；reduced-motion 下无动画；50 卡片更新可操作 |
| **数据边界级** | 反馈「待审核」文案无违规；30 天清理可用；不记录 IP/UA；无 HTTP 原始导出 |
| **口径级** | 页面所有数字带来源/时间/样本量；未校准分数一律标注；投票与准确率分列 |

### 14.2 不可接受的实现（红线）

1. 前端用随机数/固定值伪造概率或置信度；
2. 宣称「模型有 X% 把握」而未经校准（本期未做校准）；
3. 宣称 Elo 榜为「模型准确率」或「客观排名」；
4. 投票前把 `model_id` 下发到浏览器；
5. 用前端假动画冒充 SSE 流式；
6. 把某次测试集指标写成「实时业务准确率」；
7. 反馈后提示「模型已学会 / 已重新训练 / 已更新」；
8. 把「关键词与类别相关」写成「关键词导致概率上升」；
9. 把 mock/快照结果标为 live，或让 mock 数据进入统计基线；
10. 用 `document.execCommand('copy')` 作为唯一复制方案并宣称可靠。
